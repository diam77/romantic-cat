1. 문서 목적

현재까지 확정·정리된 《낭만고양이》의 세계관, 스테이지, 전투, 지원 캐릭터, 적 리스폰, 개발 프로세스를 하나의 기준 문서로 통합한다. 기존 Android 알파 프로젝트를 우선 보존하며, Codex 개발 시 이 문서를 최상위 레퍼런스로 사용한다.

스토리

재개발 예정 지역의 오래된 건물에서 엄마와 형제들과 함께 살던 턱시도 고양이. 철거 과정에서 건물이 무너지며 가족과 헤어지고, 가족이 남긴 흔적을 따라 긴 여정을 시작한다. 오래된 주택가에서 계란이, 상가 골목에서 삼순이, 시민공원에서 남순이를 차례로 만나며 세 고양이는 주인공의 가족을 찾는 동료가 된다.

재개발 지역, 주택가, 상가, 공원, 하천, 시장, 항구, 물류단지, 화물철도, 시골마을, 고가도로, 아파트, 지하주차장, 번화가, 배수로, 물류창고, 폐공장, 폐차장, 도시 외곽을 거쳐 마침내 가족이 구조되어 보호받고 있는 따뜻한 작은 마을에 도착한다.

세계관/전투 표현 원칙

  • 모든 적을 단순한 악당으로 만들지 않는다.
  • 동물은 생존·영역·두려움·배고픔·새끼 보호 등의 이유로 충돌한다.
  • 인간과 도시 시설은 작은 고양이 시점에서 거대한 위험으로 표현한다.
  • 가능한 한 적은 죽지 않는다. 패배 시 기절, 도망, 후퇴, 공격 포기, 화면 밖 퇴장 등으로 처리한다.
  • 전투의 목적은 살상이 아니라 위험을 돌파하고 가족의 흔적을 따라가는 것이다.

3. 핵심 플레이 구조

기본: 2D 연속 횡스크롤. 강제전투로 화면을 잠그는 방식은 기본적으로 사용하지 않는다. 맵 자체의 길이, 장애물, 적 배치 밀도와 조합으로 플레이 시간을 확보한다.
  • Stage별 일반 적 캐릭터 종류: 5종
  • Stage별 보스: 1종
  • 장애물은 적 5종에 포함하지 않는다.
  • 아이템 시스템은 현재 개발 범위에서 제외한다.
  • 기존 알파의 이동/공격/HP/콤보/애니메이션/HUD/대화/적/충돌 시스템을 최대한 보존한다.

스테이지 길이 및 적 스폰 포인트

Stage 1은 13개의 일반 적 스폰 포인트로 시작하고 Stage마다 1개씩 증가한다. Stage 20은 32개다. 보스는 별도다.

SpawnPoints(stage) = stage + 12 Stage 01 = 13 → Stage 10 = 22 → Stage 20 = 32

기존 최대 활성/관리 적 제한 10개는 유지한다. 실제 동시 교전은 보통 2~4개가 자연스럽도록 배치한다.

뒤로 이동 시 리스폰

  • 일반 적은 스폰 포인트 기반으로 리스폰한다.
  • 처치 후 플레이어가 충분히 멀어진 뒤 해당 구역으로 되돌아오면 다시 생성한다.
  • 플레이어 화면 내부 또는 바로 인접한 곳에서는 리스폰하지 않는다.
  • 이미 살아 있는 적은 중복 생성하지 않는다.
  • 동시 활성 일반 적은 최대 10개.
  • 보스는 리스폰하지 않는다.
  • 보스전 시작 시 일반 적 신규 리스폰을 일시 중단한다.

4. 동료/지원 시스템 — 묵·찌·빠

계란이👊 묵 · 직접 공격주인공 공격 성공 시 +1칸왼쪽에서 진입 → 추월 → 스파크 → 점프 → 위에서 아래로 강한 발톱 공격 → 넉백 → 퇴장
삼순이✌ 찌 · 회복주인공 회피 성공 시 +1칸접근 → 몸 비비기/접촉 → 작은 반짝임 → 회복 에너지 전달 → HP 점진 회복 → 퇴장
남순이🖐 빠 · 돌진연속 3 COMBO마다 +1칸. 3/6/9에서 MAX. 획득 칸은 콤보가 끊겨도 유지진입 → 정지/스파크 → 자세 낮춤 → 직선 고속 몸통 돌진 → 강한 넉백 → 반동/회복 → 퇴장

세 캐릭터 모두 게이지는 정확히 3칸. MAX 시 얼굴 아이콘 Highlight/Bounce + Glow + 짧은 효과음/진동. 소환 후 ■■■→□□□.

해금: Stage 1 없음 → Stage 2 계란(묵) → Stage 3 삼순(찌) → Stage 4 남순(빠) → Stage 5부터 전체 사용.

6. Stage 20 엔딩 구조

마을 전체를 위험 지역으로 표현하지 않는다. 전투는 마을 외곽/입구에서 마무리한다. 최종보스는 특정 실존인을 연상시키지 않는 완전한 가상 캐릭터 동물 포획업자다. 포획망, 포획틀, 포획봉 등의 장비를 사용하지만 직접적인 살상 표현은 지양한다.

마을 외곽 → 마지막 추적/전투 → 동물 포획업자 보스전 → 전투 종료 → 평화로운 마을 진입 → 가족 흔적 탐색 → 엄마·형제 재회 → 계란·삼순·남순과 함께 엔딩

7. 개발 작업 흐름

최초 전체 분석

자료/레퍼런스 분석 → 현재 Android 프로젝트 Build/구조 분석 → 현재 구현 목록 → Gap Analysis → 수정안 제안 → 사용자 승인 → Stage별 Vertical Slice → Emulator Test → 회귀 테스트 → Debug APK

Stage 완료 후 Agile 반복

현재 구현 목록 갱신 → Gap Analysis → 수정안 제안 → 승인 → 다음 Stage Vertical Slice → Emulator Test → 회귀 테스트 → Debug APK → 다음 Stage 반복

승인 게이트: Gap Analysis 이후 Codex가 임의로 대규모 구현을 진행하지 않는다. 수정안을 먼저 제시하고 승인된 범위만 구현한다.

회귀 테스트 핵심

  • 현재 Stage 신규 기능
  • 이전 Stage 정상 작동
  • 세이브/로드 및 Stage 진행 상태
  • 묵·찌·빠 해금/게이지/소환
  • 일반 적 스폰 및 뒤로 이동 시 리스폰
  • 활성 적 최대 10개 제한
  • 보스 진입/종료 및 일반 적 리스폰 중지
  • 충돌/애니메이션/HUD/대화
  • 앱 재실행
  • Debug APK 실제 실행

8. 그래픽/개발 레퍼런스 방향

  • 고전 16/32-bit 감성의 레트로 픽셀아트.
  • 세로형 Android 화면에서도 횡스크롤 플레이 가독성을 확보한다.
  • 고양이 시점을 기준으로 차량·중장비·건축물·도시 시설을 크게 느껴지게 표현한다.
  • Stage별 레퍼런스에는 배경, 주요 장애물, 일반 적 5종, 보스, 시간대/조명/분위기를 함께 정의한다.
  • Stage 1~20은 동일한 아트 디렉션을 유지하되 지역별 색감과 환경 실루엣을 명확히 차별화한다.

9. 현재 개발 우선순위

  1. 기존 Android 알파 프로젝트 Build 성공 및 구조 파악.
  2. 기존 구현 기능을 삭제/재작성하기 전에 목록화.
  3. Stage 01을 Vertical Slice 기준 Stage로 완성.
  4. 긴 횡스크롤 맵 + 13개 스폰 포인트 + 되돌아갈 때 리스폰 검증.
  5. Stage 02~04에서 계란/삼순/남순 합류 및 묵·찌·빠 순차 해금.
  6. Stage 05 이후 전체 지원 시스템과 장거리 Stage 밸런스 검증.
  7. Stage마다 스폰 포인트 +1 적용.
  8. Stage 20 가족 재회/엔딩 완성 후 전체 회귀 테스트 및 Release Candidate 준비.
