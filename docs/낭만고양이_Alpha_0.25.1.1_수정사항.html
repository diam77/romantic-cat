20. Alpha 0.25.1.1 · 보스 출현 로직 및 스테이지 장애물 공통 확정

20-1. 전 스테이지 공통 보스 출현 로직 수정

  • STAGE 01~10의 보스는 스테이지 진행 중간에 출현하지 않는다. 보스전은 반드시 스테이지 최종 구간에서 시작한다.
  • 보스 출현의 기본 조건은 플레이어가 최종 BOSS_ZONE / STAGE_END에 도달했는지 여부로 한다.
  • 시간 경과, 적 처치 수, 단순 진행도 하나만으로 보스를 호출하지 않는다.
  • 최종 구간 도달 + 해당 스테이지의 필수 전투/웨이브 완료를 확인한 뒤 보스전을 시작한다.
  • 보스전 진입 시 일반 적 신규 스폰과 일반 구간 횡스크롤을 중지하고 카메라 및 플레이어 이동 범위를 Boss Arena에 고정한다.
  • 보스 등장 연출 → 보스 생성 → bossBattle 활성화 → 보스 처치 → Stage Clear 순서를 공통 규칙으로 사용한다.

20-2. 보스 미출현 버그 Fail-safe

  • 플레이어가 스테이지 끝에 도달했는데 BOSS_ZONE Trigger가 누락되어 보스가 나오지 않는 문제를 방지한다.
  • 보스 출현은 충돌 Trigger 하나에만 의존하지 않고, playerX ≥ bossZoneStartX 또는 stageProgress ≥ 98%를 보조 조건으로 사용한다.
  • 필수 웨이브가 완료된 상태에서 최종 구간에 도달하면 BOSS_ZONE 진입을 자동 처리한다.
  • 최종 구간 도달 후 약 3초 이내 보스전 상태로 전환되지 않으면 1회에 한해 보스 생성 로직을 강제 실행한다.
  • bossSpawned 플래그로 중복 생성 방지. Stage Clear/Restart/Title 복귀 시 Boss 관련 상태를 초기화한다.
최종 진행 구간 도달 → 필수 Wave 완료 확인 → 일반 적 Spawn OFF → Stage Scroll OFF → Boss Arena Lock → Boss Intro → Boss Spawn → Boss Battle → Boss Defeat → Stage Clear

20-3. 장애물 설계 공통 원칙

  • 적 캐릭터 정보와 장애물 정보를 분리한다. 이 항목의 대상은 환경 장애물/시설물뿐이며 일반 적·중간 적·보스 캐릭터를 포함하지 않는다.
  • 장애물은 단순 장식이 아니라 점프, 숙이기, 우회, 이동 속도 조절, 전투 위치 변화 등 실제 플레이 리듬에 사용한다.
  • 같은 박스/상자 오브젝트를 전 스테이지에 반복 사용하지 않는다. 각 스테이지의 장소성과 스토리에 맞는 고유 장애물을 우선한다.
  • 장애물 Collision 범위는 보이는 형태와 최대한 일치시켜 억울한 충돌을 방지한다.
  • 진행 불가능한 완전 봉쇄 배치는 금지하며, 통과 방법이 플레이어에게 시각적으로 읽히도록 한다.

20-5. Alpha 0.25.1.1 회귀 테스트

  • 각 Stage에서 보스가 진행 중간에 생성되지 않는지 확인한다.
  • 각 Stage 최종 구간에 도달하면 보스가 정상 출현하는지 확인한다.
  • BOSS_ZONE Trigger가 누락되거나 경계에서 빠르게 이동해도 98%/STAGE_END 보조 판정으로 보스가 출현하는지 확인한다.
  • 보스 출현 시 일반 적 신규 Spawn과 횡스크롤이 정지하는지 확인한다.
  • 보스가 중복 생성되지 않는지 확인한다.
  • 보스 처치 후에만 Stage Clear가 실행되는지 확인한다.
  • 각 Stage 장애물이 진행을 완전히 막지 않고 점프/숙이기/우회 동작과 정상 Collision 되는지 확인한다.
